### Cause
Working theory. The replay binds a bare builtin type name through `search_path`, and a relation of the same name shadows it.

1. `driftFlight` replays the snapshot under `SET LOCAL search_path TO <scratch schema>, pg_catalog, pg_temp`, so the scratch schema is searched before `pg_catalog` ([drift.ts](https://github.com/bjornpagen/grizzle/blob/65203c443fa969cc47c539666a998436595f42fe/packages/grizzle/src/adapter/admission/drift.ts#L505-L507)). PostgreSQL searches `pg_catalog` first only when the path does not list it ([The System Catalog Schema](https://www.postgresql.org/docs/current/ddl-schemas.html#DDL-SCHEMAS-CATALOG)).
2. `printType` writes a builtin type without a schema ([print.ts](https://github.com/bjornpagen/grizzle/blob/65203c443fa969cc47c539666a998436595f42fe/packages/engine/src/sql/print.ts#L174-L175)).
3. The comment on `builtinTypeNames` says these names "resolve ahead of any user schema, so they print unquoted" ([ast.ts](https://github.com/bjornpagen/grizzle/blob/65203c443fa969cc47c539666a998436595f42fe/packages/engine/src/sql/ast.ts#L32-L35)). Under the replay's path, `text`, `uuid` and `money` resolve to the scratch schema first, as the psql session shows.
4. Once the replay creates the table `text`, its row type is what a bare `text` names in every later statement. A composite type takes no collation, which gives SQLSTATE 42804 for a column declared with one. A later column declared without a collation binds to the composite without an error, which gives the false `Drifted`.
5. The refusal surfaces as `DriftUnchecked` ([errors.ts](https://github.com/bjornpagen/grizzle/blob/65203c443fa969cc47c539666a998436595f42fe/packages/grizzle/src/adapter/migrate/errors.ts#L629-L666)).

### Impact
A schema with such a relation cannot be installed through grizzle at all, because `grizzle migrate` exits 1 on every run even though every folder applied. The printed fix line, "undo the change made outside a migration", points at a change that was never made.

### Not confirmed
- Whether these names are meant to be refused at compile time. No rule was found in the README, the packaged agent guide or the compiler, and `grizzle generate` and `grizzle check` accept each schema above.
- Relations named `Regclass`, `Record` or `Trigger` were not run. The range names are not reachable through a relation name: the name converter writes `Int4range` as `int_4_range`. `jsonb` has no field type. A closed enum or a contract named `Text`, `Uuid` or `Money` was not run.
- Not run on an unpatched PostgreSQL.

### Fix direction
Possible change, untested. Either run the replay under `SET LOCAL search_path TO pg_catalog, <scratch schema>, pg_temp`, or run it under `pg_catalog, pg_temp` with no scratch schema, as [drift.ts](https://github.com/bjornpagen/grizzle/blob/65203c443fa969cc47c539666a998436595f42fe/packages/grizzle/src/adapter/admission/drift.ts#L511) already does for the reads that follow. Every object the replay creates carries its schema (`ObjectName.schema` is required in [ast.ts](https://github.com/bjornpagen/grizzle/blob/65203c443fa969cc47c539666a998436595f42fe/packages/engine/src/sql/ast.ts#L5-L8), and the [scratch hooks](https://github.com/bjornpagen/grizzle/blob/65203c443fa969cc47c539666a998436595f42fe/packages/grizzle/src/adapter/admission/drift.ts#L275-L286) move named types, functions and extension objects into the scratch schema), so neither option changes what the replay creates.

### Summary
The first call of the `alternatives` reverse law function in each backend compiles a body with one `WHEN` per (participating table x handle) cell, plus one `IF NOT FOUND` refusal per cell when a handle has no arm, and that compile time grows as the square of the cell count. In `grizzle generate` output with one unarmed handle the first call takes 0.36 s at 43 handles, 5.25 s at 85 and 25.72 s at 128, and with every handle armed it takes 0.62 s at 85 and 2.99 s at 128. The unarmed handle multiplies the cost about 8 times at the same size (59,008 lines against 15,578 at 85 handles).

Ran `grizzle generate` on a standalone schema and timed the generated functions on PostgreSQL 19rc1 (grizzle's development cluster, `jit = off`), one run per row. Read at `bjornpagen/grizzle@65203c4`.

### Cause
grizzle's part: the function holds (participating tables) x (handles) `WHEN` arms (Code path 5), 16,512 at 128 handles, and with an unarmed handle one 8-line `IF NOT FOUND` refusal block per arm (Code path 3), against 129 refusals when every handle is armed. The `fixed` shape under Fix direction removes the second term and returns the same results. `unlessFound` is used outside `alternatives` only at `mirrors/index.ts:51`, where it is one probe per branch of constant size, so no other family multiplies in this way.

The measured facts:

- The cost is paid by the first call in a backend, and `CREATE FUNCTION` pays the same compile once (5.17 s for the 85-handle function with one unarmed handle). With `PGOPTIONS='-c check_function_bodies=off'`, `CREATE FUNCTION` of the same file takes 10.299 ms and its first `COMMIT` still takes 4,889.690 ms. The time is PL/pgSQL compilation of the body.
- The time follows the number of `WHEN` and `IF` statements, not the bytes (see the table).
- Two controls with no grizzle: a function of 10,000, 20,000 and 40,000 flat `PERFORM 1 FROM t WHERE id = x;` statements creates in 12.4, 24.6 and 47.6 ms, which is linear. A function with one `CASE` of 10,000, 20,000 and 40,000 `WHEN i THEN PERFORM 1;` arms creates in 640.014, 2,766.804 and 12,320.484 ms, which is quadratic.

Working theory for the quadratic term, traced in source and not profiled. PostgreSQL 19rc1 (tag `REL_19_RC1`) `pl_scanner.c` reads `/* be correct, but not fast, if input location goes backwards */` and calls `location_lineno_init`, which rescans the body line by line from the start.

https://github.com/postgres/postgres/blob/0b8bff042a997fe50fcd1c4c83b9ef1cc9ed8a89/src/pl/plpgsql/src/pl_scanner.c#L581-L583

Every `CASE ... WHEN` computes its line number after its body is parsed (`plpgsql_location_to_lineno`), and so does every `IF`.

https://github.com/postgres/postgres/blob/0b8bff042a997fe50fcd1c4c83b9ef1cc9ed8a89/src/pl/plpgsql/src/pl_gram.y#L1269

https://github.com/postgres/postgres/blob/0b8bff042a997fe50fcd1c4c83b9ef1cc9ed8a89/src/pl/plpgsql/src/pl_gram.y#L1196

Each `WHEN` and each `IF NOT FOUND` then pays one scan from the top. grizzle's two patches under [`scripts/pg/patches/`](https://github.com/bjornpagen/grizzle/tree/65203c443fa969cc47c539666a998436595f42fe/scripts/pg/patches) touch neither file.

### Impact
Every new connection's first law-checked write pays the compile, so a pool pays it once per connection: 0.36 s at 43 handles and 5.25 s at 85 with one unarmed handle, 0.62 s at 85 with every handle armed. `grizzle generate` writes a 99.4 MB `snapshot.json` for the 85-handle schema with one unarmed handle against 17.6 MB, and `DbLayer.make` takes that file when the app starts ([README.md:1062](https://github.com/bjornpagen/grizzle/blob/65203c443fa969cc47c539666a998436595f42fe/README.md#L1062)).

### Fix direction
Possible change, tested on `gen-fix.sh`'s SQL and not on grizzle. The tested shape has one refusal per branch after `END CASE`, as the armed shape has, and `PERFORM 1;` in the `ELSE` so `FOUND` stays true. The raised error and its `DETAIL` are the same, and a schema with every handle armed generates the same text as today.

A deeper direction, untested: a function that dispatched the `CASE` once per call would grow as tables + handles and not as their product. That would answer the growth clause.
